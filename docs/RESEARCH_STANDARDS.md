# 연구·판정 기준 (모든 에이전트 구속)

이 리포에서 일하는 **모든 에이전트**(Orca 워커, Codex 세션, 사람)에 적용된다. 수정 권한은 오케스트레이터에게만 있고 다른 에이전트는 인용만 한다.

- 결정의 출처는 `docs/DECISIONS.md`(OD-N). **이 문서는 결정을 다시 서술하지 않고 번호로 가리킨다.**
- `docs/architecture/CONTROL_PLANE_2026-08-14.md`의 KD-N은 그 문서 안에서 유효하며, 원장과 충돌하면 원장이 이긴다.
- 플릿 운영 규칙(누가 병합하는가, 보고 경로)은 제어면의 `orca/PROTOCOL.md`에 있다.

---

## 1. 무엇이 근거로 인정되는가

### 1-1. 보고의 최소 요건

세 가지를 갖추지 않은 보고는 근거로 쓰지 않는다.

1. **돌려본 명령과 결과를 실측으로 적는다.** 짐작과 실행 결과를 같은 문단에 섞지 않는다.
2. **확인 못 한 것을 명시적으로 분리한다.** 범위 밖이면 범위 밖이라고 적는다.
3. **전칭 주장에는 범위를 함께 적는다.** "전수 확인", "유일한", "전부"는 무엇을 훑었는지 없이는 쓸 수 없다.

세 요건은 전부 실제 사고에서 나왔다. ①②는 2026-08-16에 여러 번 잘못된 병합을 막았고, ③은 "쓰기 엔드포인트는 1개뿐"이라는 주장이 FastAPI 앱 기준으로만 참이었던 사고를 냈다(`b_engine/server.py`가 `0.0.0.0`에 무인증으로 열려 있었다).

### 1-2. 방법 요건

주장의 종류에 따라 아래를 갖춘다. 하나라도 빠지면 그 결과는 판정 근거가 아니다.

| 주장의 종류 | 요건 |
|---|---|
| 집계·그룹·선택 | 축에 맞는 플라시보 — 달력·일자 주장은 date-shuffle, 횡단면 주장은 랜덤티커·랜덤섹터 relabel |
| 조건 비교 | **같은날·같은폴드 페어**. 독립 평균을 나란히 놓는 것은 무효 |
| 피처 증분 | 시드 ≥ 3 + 등량 노이즈 대조. **증분 0.3pp 미만은 이 프로토콜로 주장 불가**(측정하한, §19) |
| 중첩창 통계 | 블록 부트스트랩(5일 블록) + 순환이동 플라시보. iid 부트스트랩은 §33에서 이미 틀렸다 |
| `px_long` 기반 백테스트 | 생존편향 대조 또는 편향 크기 명시(실측 보정상수 **−0.28pp@20d / −0.67pp@60d**) |
| 모든 예측 | 누출 컬럼(`ft_*` / `exec_*` / `cl_*`) 미사용. 한 번 쓰고 +40% 가짜 결과가 나온 적이 있다 |
| 체결 가정 | 익일 `max(open, level)`. 같은 봉·종가 체결은 갭을 엣지로 오인한다. 장중 체결을 새로 가정하면 분봉으로 별도 검증하고, 커버리지 없는 구간은 **판정 불가**로 표시 |
| 알파 주장 | 횡단면 demean 또는 지수 헤지로 베타를 분리 |

### 1-3. 실격 사유

문턱을 넘어도 실격되는 경우가 있다. 문턱은 효과 크기를 묻고 실격은 **귀속**을 묻는다.

- **같은날 시장중립 대조에서 상위 픽이 하위 픽보다 못하면 실격**(OD-3). 반등 베타가 알파로 통과하는 것을 막는다.
- 사전등록 킬 기준 위반(OD-19).

## 2. 사전등록

연구는 결과를 보기 전에 등록한다. 템플릿은 `docs/research/PREREG_MECH_FLOW_CALENDAR_2026-08.md`.

필수: 가설을 독립적으로 진술 · 공통 게이트 · **킬 기준을 수치로 사전 고정** · 중요도 하한.

**킬 기준은 기계 판독 가능한 형태로 적는다**(OD-19). 산문으로만 적힌 킬 기준은 아무도 다시 읽지 않는다 — §40이 그렇게 적었고 위반이 두 달 뒤 우연히 발견됐다. 검사기가 매일 대조하고 발동 시 정지 지점으로 올린다.

같은 원장·같은 라벨 위에서 조건을 조합해 새 셀을 찾는 것은 **낚시 금지 규칙 위반**이다.

## 3. 목표와 승격

### 3-1. 목표 (OD-4)

**승률 65% · 수익 5% 이상 · 3일 이내 터치.**

달성해도 만족하지 않는다. 기준을 계속 점검하고 달성 시 상향한다(OD-5) — 단 상향은 래칫 3조건 통과 후, 임의 수치가 아니라 **달성 레인의 실측 분포**에서 뽑는다.

기존 문서의 "75% 정확도 / 15% 수익률"은 OD-4가 대체한다. §40이 상한을 ~+8.3%/yr로 재계산한 뒤에도 그 수치가 설계 근거로 인용되고 있었다.

3일 계약은 **병행 측정부터** 한다(OD-6). 계약 창을 줄이면 승자가 더 잘려 현재 진단("승리는 터치익절로 잘리고 손실은 안 잘린다")을 악화시킬 수 있다.

### 3-2. 발행 자격 (OD-1)

순 EV 부트스트랩 CI 하단 > 0 · n ≥ 30 이고 고유일 ≥ 20 · 재귀게이트 CONFIRM 이상.

세 조건을 모두 채운 레인만 발행한다. **문턱은 올리지 않는다**(OD-2) — 기준이 지나치면 엣지가 아예 나오지 못한다.

### 3-3. 승격 경로

```
shadow(원장만) → 관측(발행 없음) → 발행 자격(OD-1) → 낮은 f → 래칫 3조건 → f 상향
```

- 자격 통과 전 사이징 0. 통과해도 §20의 f=0.10을 처음부터 주지 않는다(OD-7).
- 래칫 3조건: 성숙시차 재확인 · n ≥ 100 · EXCEED 10영업일 유지.
- 게이트는 **발행 스트림만** 판정한다(OD-15). 라우팅되지 않는 픽으로 발행 레인을 강등하지 않는다.
- 정지 레인은 정지 시각 이후 표본으로 판정하지 않는다(OD-14).
- 게이트가 판정하지 않는 레인(UNGATED)은 **발행 불가**다(OD-17).

### 3-4. 챔피언 (OD-9, OD-10)

카테고리는 다섯이다: 코스피 스윙 · 코스피 장중 · 코스닥 스윙 · 코스닥 장중 · 나스닥.

각 카테고리에 챔피언 하나를 둔다. 자격 미달이면 **공석**으로 선언하고 자격 없는 최선을 앉히지 않는다. 공석 카테고리는 발행 정지이며, 할 일은 자격을 갖춘 레인을 새로 만들어 내는 것이다.

순위는 승률·수익률로 정하고 충돌 시 수익률을 우선한다. 꼬리 지표(하위10% 평균·최악·승자평균·고유일수)는 기준에서 빠지되 보조 열로 계속 싣는다 — 승률 ~70%는 터치익절 계약이 기계적으로 만드는 값이라 레인 간 변별력이 없다.

챔피언 대비 비교는 **같은 기간·같은 유니버스**에서 한다. 각자계약(운영 성과)과 동일계약(신호 품질)을 **둘 다** 산출한다 — 느슨한 계약을 쓰면 승률이 높게 나오고 그건 신호 우위가 아니다.

## 4. 연구 방향

**근본 원인 해결이 신규 탐색보다 앞선다**(OD-8). 원인을 개선한 뒤에 연구한다.

현재 최우선 근본 원인은 **출구계약 비대칭**이다. 네 레인이 전부 승률 68~73%에 평균 음수로 같은 모양이고, 손익분기 승률 74.8% 대비 3.4pp 부족하며, 손익비 16.0% 개선이 손익분기점이다. 계약이 공통 원인이므로 고치면 다섯 카테고리에 동시에 듣는다. 단순 손절은 이미 기각된 방향이다(`a_exit_policy_lever`: 스톱 추가는 EV를 반토막낸다).

§37의 "보유 데이터 프론티어 종결"과 §40의 "라이브 부검 우선, 직교 신규 데이터 차선"은 유효하다.

## 6. 이 기준을 어긴 보고를 만났을 때

검증자는 위반 자체를 **반려 사유로 적는다**. 벌칙은 없다. 구현자는 고쳐서 다시 낸다.

2026-08-16에 구현자가 범위 없는 전칭 주장을 지적받고 스스로 이전 보고서에 정정 문구를 박아 넣었다 — 그 보고서를 근거로 쓸 다음 사람이 틀린 주장을 물려받지 않게. 그 반응이 이 규칙이 원하는 것이다.
